# GraphQL Code-First Architecture

How the 4eye project uses NestJS code-first GraphQL with TypeScript types.

> **See [TYPE_ORGANIZATION.md](TYPE_ORGANIZATION.md)** for type system details.

---

## Code-First vs Schema-First

**Code-First (this project):**
- Write TypeScript types and decorators
- NestJS auto-generates GraphQL schema
- Types are source of truth

**Schema-First (not used):**
- Write `.graphql` schema files first
- Generate TypeScript types from schema
- Schema is source of truth

---

## Architecture Flow

```
TypeScript Types → NestJS Decorators → Generated Schema
(@4eye/types)      (apps/api/)         (@4eye/graphql-schema)
```

**1. Define types in `@4eye/types`**
```typescript
// packages/@4eye/types/src/inputs/room.ts
export interface CreateRoomInput {
  name: string;
  description?: string;
  organizationId?: string;
}
```

**2. Use in NestJS resolvers with decorators**
```typescript
// apps/api/src/modules/rooms/rooms.resolver.ts
import type { CreateRoomInput } from '@4eye/types';
import { Resolver, Mutation, Args } from '@nestjs/graphql';

@Resolver()
export class RoomsResolver {
  @Mutation(() => Room)
  async createRoom(@Args('input') input: CreateRoomInput) {
    return this.roomsService.create(input);
  }
}
```

**3. NestJS generates GraphQL schema**
```graphql
# packages/@4eye/graphql-schema/schema.gql (auto-generated)
type Mutation {
  createRoom(input: CreateRoomInput!): Room!
}

input CreateRoomInput {
  name: String!
  description: String
  organizationId: String
}
```

**4. Frontend/tools consume schema**
```typescript
// apps/4eye-web - GraphQL operations use generated schema
import { gql } from '@apollo/client';

const CREATE_ROOM = gql`
  mutation CreateRoom($input: CreateRoomInput!) {
    createRoom(input: $input) {
      id
      name
    }
  }
`;
```

## Package Roles

### @4eye/types
**Purpose:** Source TypeScript types
- Domain entities (User, Room, Session)
- Input DTOs (CreateRoomInput, UpdateRoomInput)
- AI response interfaces

**Used by:** Backend resolvers, frontend queries, shared business logic

### @4eye/graphql-schema
**Purpose:** Auto-generated GraphQL schema output
- Contains `schema.gql` generated by NestJS
- Generated from TypeScript + decorators

**Used by:** GraphQL clients, tooling, documentation generation

---

## Why Separate Packages?

**Benefits:**
- Clear separation: source types vs generated artifacts
- Clients can import schema without all type definitions
- Schema can be published/versioned independently
- Build pipeline outputs to dedicated location
