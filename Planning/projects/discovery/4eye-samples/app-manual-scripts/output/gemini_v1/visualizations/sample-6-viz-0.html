📊 Big O Notation: Growth of Time Complexity

Visualizing How Algorithms Scale

O(1) - Constant Time

Growth: No growth at all!

Example: array[5]

Accessing an array element by index always takes the same time, no matter how big the array is.

⚡ Performance: Best possible

O(log n) - Logarithmic Time

Growth: Very slow growth

Example: Binary Search

Eliminates half the possibilities with each step. Doubling the input only adds ONE extra operation.

🚀 Performance: Excellent

O(n) - Linear Time

Growth: Proportional growth

Example: for (let i = 0; i < n; i++)

A simple loop through all elements. Double the input, double the time.

✅ Performance: Good

O(n log n) - Log-linear Time

Growth: Moderate growth

Example: Merge Sort, Quick Sort

Efficient sorting algorithms. Much better than O(n²) for large datasets.

👍 Performance: Pretty good

O(n²) - Quadratic Time

Growth: Rapid exponential growth

Example: Nested loops

Comparing every element with every other element. Double the input, 4x the time!

⚠️ Performance: Poor for large data

🔥 Real-World Impact: 1,000,000 Items

Complexity Operations Estimated Time (1M ops/sec)
O(1) 1 0.000001 seconds
O(log n) ~20 0.00002 seconds
O(n) 1,000,000 1 second
O(n log n) ~20,000,000 20 seconds
O(n²) 1,000,000,000,000 🔴 11.5 DAYS!

This is why choosing the right algorithm matters!
