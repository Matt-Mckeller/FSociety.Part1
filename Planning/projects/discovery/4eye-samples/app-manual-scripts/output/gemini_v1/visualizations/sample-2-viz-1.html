📚 Big O Complexity Cheat Sheet 📚

Your Quick Reference Guide to Algorithm Efficiency

Notation Name Growth Rate Example from Lecture Practical Impact
O(1) Constant Flat Accessing array by index Extremely fast
O(log n) Logarithmic Very slow Binary search Very efficient for large data
O(n) Linear Proportional Simple loop through array Scales predictably
O(n log n) N log N Super-linear Merge sort, Quick sort Standard for efficient sorting
O(n²) Quadratic Exponential Nested loops (all pairs) Becomes unusable for large datasets

🎯 Key Takeaways from the Lecture

1. Focus on worst-case: When analyzing algorithms, we focus on the worst-case scenario to guarantee maximum time.

2. Scale matters: With 1 million records, O(n²) performs 1 trillion operations (days), while O(n log n) only performs ~20 million (seconds).

3. Foundation of scalable software: Choosing the right algorithm is crucial for building software that can handle growth.

4. Input size is key: Big O describes how runtime grows as input size increases, not the exact runtime.
